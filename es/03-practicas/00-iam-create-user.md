# Crear un usuario IAM con acceso a la consola

## Objetivo

Crear el usuario `demo-user-aws` con acceso a la consola de AWS y permisos de administrador, para dejar de usar la cuenta root en el trabajo diario.

## Prerrequisitos

- Una cuenta de AWS con sesión iniciada como usuario root.
- MFA activado en el root (recomendado antes de continuar).

## Pasos

### 1. Abrir IAM

1. En la barra de búsqueda de la consola escribe `IAM` y abre el servicio.
2. En el menú de la izquierda elige **Users**.
3. Pulsa **Create user**.

### 2. Datos del usuario

1. En **User name** escribe `demo-user-aws`.
2. Marca la casilla **Provide user access to the AWS Management Console**.
3. Si la pantalla muestra la pregunta sobre el tipo de usuario, elige **I want to create an IAM user**. * En algunas cuentas esta pregunta no aparece.
4. En la contraseña elige una de estas opciones:
   - **Custom password**: escribes la contraseña tú.
   - **Autogenerated password**: AWS la genera.
5. **Users must create a new password at next sign-in** obliga al usuario a cambiar de contraseña la primera vez.
6. Pulsa **Next**.

### 3. Permisos

1. En **Permissions options** elige **Attach policies directly**.
2. En el buscador de políticas escribe `AdministratorAccess`.
3. Marca la casilla de **AdministratorAccess** (tipo AWS managed, job function).
4. Pulsa **Next**.

> Nota: AWS muestra una recomendación de usar grupos en lugar de asignar políticas directamente al usuario. Para esta práctica se puede ignorar. Si prefieres seguir esa buena práctica, elige `+Add user to group`, crea un grupo (por ejemplo `administradores`), asígnale la política y agrega el usuario al grupo.

### 4. Revisar y crear

1. En la pantalla de revisión, comprueba el nombre, el acceso a la consola y la política.
2. La sección **Tags** es opcional. Son pares de clave y valor que sirven para organizar recursos y separar costos. 
3. Pulsa **Create user**.

### 5. Guardar los datos de acceso

La pantalla final muestra la URL de inicio de sesión, el nombre de usuario y la contraseña.

1. Puedes pulsar **Download .csv file**.
2. Guarda la URL de inicio de sesión, porque es distinta a la del root.

> Nota: La contraseña no se vuelve a mostrar. Si la pierdes, deberás restablecerla desde IAM.

## Verificación

1. Abre una ventana de incógnito del navegador.
2. Entra a la URL de inicio de sesión que descargaste.
3. Inicia sesión con `demo-user-aws` y su contraseña.
4. Abre el servicio IAM. Si puedes ver la lista de usuarios, los permisos funcionan.


## Errores comunes

| Problema | Causa probable | Solución |
|---|---|---|
| No aparece la opción de acceso a la consola | No se marcó la casilla en el primer paso | Crear el usuario de nuevo, o habilitar el acceso desde la pestaña Security credentials del usuario |
| No encuentro la política AdministratorAccess | El buscador filtra por tipo | Escribe el nombre completo y revisa que no haya otros filtros activos |
| Access Denied al abrir un servicio | La política no quedó asignada | Entra al usuario, pestaña Permissions, y comprueba que aparece AdministratorAccess |
| No puedo iniciar sesión | Se usó la URL del root, un ID de cuenta o contraseña incorrecta | Usar la URL de inicio de sesión que mostró AWS al crear el usuario |
| Perdí la contraseña | La contraseña solo se muestra una vez | Restablecerla desde IAM, en Security credentials del usuario  o busca el csv si se descargó |

## Seguridad

- No subas el archivo `.csv` de credenciales al repositorio. El `.gitignore` ya bloquea los archivos `.csv`.
- No publiques capturas donde se vea el ID de cuenta ni la contraseña.

## Limpieza

Si el usuario fue solo para una demo, puedes eliminarlo al terminar: IAM, Users, selecciona `demo-user-aws` y pulsa **Delete**.
